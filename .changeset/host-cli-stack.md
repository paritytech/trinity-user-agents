`truapi-host` runs against any Trinity stack with `--stack <descriptor URL | stack link | file>` (or `HOST_CLI_STACK`), for example `truapi-host --stack 'polkadotapp://stack?key=0x…&url=…' signing-host`, so forks and staging instances whose genesis differs from a built-in network work without a new release. The stack supplies the People, Asset Hub and Bulletin endpoints and genesis hashes, the identity backend from its `dub` service, the TLD and the dotNS `popController`, and an endpoint that reports a genesis other than the descriptor's stops the command before it runs. The product namespace is `--network` when given, otherwise the descriptor's `id` without a trailing `-fork`. A stack carrying Polkadot's genesis hashes, the `dot` TLD or the `polkadot` namespace is refused, and so is `--chain-backend light-client` with `--stack`. `paseo-next-v2` and `previewnet` are now built-in stacks: the CLI reads the descriptor their operators publish, falls back to the signed copy the release ships when it is unreachable, and prints a line when the published one is newer and in use. `HOST_CLI_PEOPLE_WS`, `HOST_CLI_ASSET_HUB_WS`, `HOST_CLI_BULLETIN_WS` and `HOST_CLI_LOCAL_NETWORK_CONFIG` are gone; use `--stack` with a local descriptor instead. `local-network-check` is now `network-check`, which prints the same JSON for any network or stack.
