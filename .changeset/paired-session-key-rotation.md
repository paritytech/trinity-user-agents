A pairing host moves its paired session to new keys once its keys are more than a day old, checking after each restore and once an hour while a session is selected. The core sends the signing host a `RotateSessionRequest`, SSO message 25, signed by the new statement key, and the signing host answers with `RotateSessionResponse`, message 26, which is `Ok` or a `RotateSessionError`: `Unsupported`, `Replaced` or `Rejected`. The new keys wait in the new `PendingSessionRotation` core storage slot until the answer arrives, so a lost answer or a restart sends the same request again. Once answered, the core stores the session on the new keys with its pairing time and its allowance and automatic-signing grants. A signing host that refuses the change, or cannot decode the request, leaves the session on its keys, and the next restore asks again; `Replaced` ends the session. The core's own signing host answers `Unsupported`. A signing host's `Disconnected` for keys with an unanswered change sends the change again and ends the session only when the change was not served. Hosts back `PendingSessionRotation` with the same store as `AuthSession`, shared the same way: a host that routes core storage slots by key, as dot.li does, routes it with `AuthSession`.
